# 数据文件格式（schemaVersion 1）

生产数据是单个 UTF-8 JSON 根对象，固定包含 `schemaVersion`、`revision`、`savedAt`、`accounts`、`shops`、`dishes`、`carts`、`orders`。根对象和各实体均采用严格字段集合：缺字段、未知字段、错误 JSON 类型、未知枚举会导致整份文件拒绝加载。

- ID 是不带花括号的小写完整 UUID。
- 金额单位为分，JSON 中必须是 JavaScript 精确整数范围内的整数；业务规则再施加价格、数量、合计和收入边界。
- 时间使用 UTC ISO 8601 毫秒格式，例如 `2026-09-01T10:00:00.000Z`。可空时间和可空骑手字段显式写为 `null`。
- 二进制盐和密码派生值使用标准 Base64。W03 只保证字段无损往返；密码生成和认证属于 W04。
- 角色、订单状态、支付状态和历史动作使用 `data/jsoncodec.cpp` 中定义的稳定英文值，中文标签不进入持久化协议。

加载在结构解析后调用 `OrderPolicy::validateAll()`，统一检查 UUID、唯一性、引用、金额、状态与支付组合、时间线和历史重放。任一错误均拒绝整份快照，不做部分加载。

保存前执行同一全局校验。若主文件已存在，先验证它，再用 `QSaveFile` 将上一有效快照原子写入 `<主文件>.bak`；备份成功后才原子替换主文件。主文件不存在时第一次保存不创建备份。主文件缺失或损坏且备份验证有效时，`load()` 返回 `RecoveryAvailable`，由 W08 的用户确认流程决定是否恢复，数据层不会自动覆盖主文件。

文件上限为 100 MiB，订单上限为 10,000。高于当前 schemaVersion 的文件返回 `UnsupportedVersion`，不得降级覆盖。
